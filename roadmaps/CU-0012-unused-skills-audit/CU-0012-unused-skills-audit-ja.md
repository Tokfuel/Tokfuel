## はじめに

持っているのに使っていないスキルを見つけます。ユーザーが git リポジトリの集まっている
ディレクトリ（例: `~/ghq/github.com/akidon0000`、`~/dev`）を 1 つ以上指定すると、アプリが
そこにあるスキル定義を発見し、トランスクリプト上の実際のスキル呼び出しと突き合わせて、
スキルごとの最終使用日を一覧します。一度も呼ばれていないものが浮かび上がります。

## 動機

スキルの棚は書き込み専用で育ちます。スキルは作られ、プロジェクトは移ろい、数十の定義の
どれがまだ働いているのか誰にも分かりません。アプリはすでにトランスクリプトからスキル
呼び出しをデコードしています（Skills タブ）が、使用実績だけでは「存在するのに呼ばれて
いないもの」は見えません。「ディスク上に存在するスキル」と「トランスクリプトに現れる
スキル」を結合してはじめて、棚卸しが監査になります。削除候補、放置されたディレクトリ、
死荷重が見えます。トランスクリプト内容の分析に踏み込む競合は存在せず、本アプリの主要な
差別化軸を深める提案です。

## 詳細設計

- **明示的な複数ルート指定。** 設定画面のリストに、`NSOpenPanel` でディレクトリを複数
  追加できます（CU-0005 のスキャン場所と同じく security-scoped bookmark で保持）。指定
  されていない場所は一切走査しません。
- **走査はルート直下と、そのちょうど 1 階層下まで。** 指定ルート `R` ごとに、見るのは
  `R` 自身と直接の子 `R/<repo>` だけで、再帰的には降りません。それぞれの場所で確認する
  のも既知のエージェント設定ディレクトリのみです。
  - `.claude/skills/<name>/SKILL.md`（Claude Code のスキル）
  - `.claude/commands/*.md`（スラッシュコマンド）
  - `.cursor/rules/`（Cursor のルール）ほか、他エディタのエージェント設定の同様に浅い
    既知の場所（リストは拡張可能）
  リポジトリ内のそれ以外のファイルは読みも索引もしません。走査は速く予測可能で、プライ
  バシー面でも保守的です（ソースツリーをクロールしません）。
- **使用実績との結合**: トランスクリプトからデコード済みのスキル / コマンド呼び出しを、
  スキル名（可能ならプロジェクトパスも）で照合します。グローバルスキル
  （`~/.claude/skills/`）は現状どおりデフォルトで棚卸しに含めます。
- **UI**: Skills タブに「Audit」ビューを追加します。スキル・定義リポジトリ・最終使用日・
  呼び出し回数（30 日 / 全期間）の表で、「未使用」フィルタとソートを備えます。未使用とは
  走査できたトランスクリプト履歴の中でゼロ回のことで、履歴の実際の期間を明示します
  （トランスクリプトは削除されるため「観測できた直近 N 日で未使用」という表現にします）。
- **更新**: 手動の再走査と、アプリの通常の更新間隔での再走査。結果はキャッシュします。

## 検討した代替案

**指定ルートの再帰走査。** 要件どおり不採用。リポジトリ集積地は巨大になりえます
（node_modules やビルドツリー）。深さ制限つきで既知ディレクトリだけを見る方式なら計算量
はリポジトリ数に比例し、何を読んだのかでユーザーを驚かせることもありません。

**リポジトリルートの自動検出（ghq root や `~/src` など）。** v1 では不採用。明示的な指定
のほうが同意が曖昧になりません。「ghq root を提案」ボタンのような補助は後から足せます。

**「このスキルはどこでも未使用」と断定する表現。** 不採用。トランスクリプトは他のマシン
や削除済みの履歴をカバーしないため、UI では常に観測できた期間を添えます。
