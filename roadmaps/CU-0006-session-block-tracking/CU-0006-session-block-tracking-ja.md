## はじめに

Claude Code のプラン制限が適用される「5 時間のセッションブロック」を追跡します。現在の
ブロックで消費したトークン量、リセットまでの残り時間、バーンレート（トークン/分）、この
ペースで使い切る予測時刻を表示します。要点はメニューバーにも出し、しきい値を越えたら通知
します。

## 動機

サブスクリプション（Pro / Max）のユーザーにとって本当に痛いのは金額ではなく、作業の途中で
5 時間ウィンドウの上限に当たることです。主要な競合はどれもここを中心機能にしています。
ccusage には `blocks --live` があり、Claude Code Usage Monitor はバーンレートと到達予測の
ために作られたツールで、CCSeva や Usage4Claude はブロックの消費率をメニューバーに出して
います。いまの本アプリは「いくら使ったか」には答えますが、ユーザーが一日に何度も気にする
「あとどれだけ使えるか」には答えられません。必要なデータはすでに走査しているトランスクリ
プトの中に全部あり、新しい入力は要りません。

## 詳細設計

- **ブロック検出**: ccusage と同じ方式で、トランスクリプトのエントリを 5 時間ブロックに
  まとめます。間隔が空いたあとの最初のメッセージでブロックが始まり、開始時刻は正時に切り
  下げます。「今」を含むブロックがアクティブです。`TranscriptScanner` を入力とする純粋で
  テスト可能な型（`SessionBlockTracker` など）として実装し、python3 は使いません。
- **バーンレート**: アクティブブロック内のタイムスタンプから、トークン（と推定コスト）の
  毎分消費量を求めます。
- **到達予測**: ブロックの予算（トークンまたは推定コスト。プランは正確な上限を公開して
  いないため、プリセットつきのユーザー設定値とします）に対し、バーンレートから枯渇時刻を
  外挿し、リセット時刻と比べて表示します。
- **メニューバー**: アイコンの横に `42% · 2h13m` のようなコンパクト表示をオプションで
  出します。色分けは CU-0001 の予算アラートの規約を踏襲します。
- **通知**: `BudgetMonitor` と同じ「レベルが上がった立ち上がりだけ・ブロックごとに再アーム」
  の状態機械で通知します（しきい値 70% / 90% などを `SettingsView` で設定）。
- **UI**: `PopoverView` に「Session」セクション（またはタブ）を追加し、進捗バー・リセット
  までのカウントダウン・バーンレートのスパークラインを表示します。

## 検討した代替案

**Anthropic のレートリミット / OAuth エンドポイントに問い合わせてサーバー側の正確な%を
出す。** これは別提案の [CU-0007](../CU-0007-server-quota-readout/CU-0007-server-quota-readout-ja.md)
とします。ローカル限定の原則に触れるためオプトインとして切り出し、本項目は CU-0007 を
有効にしなくても完全オフライン・セットアップ不要で動くようにします。

**ccusage をラップする。** 不採用。Node / npx への依存が増え、ゼロセットアップと依存追加
禁止の原則に反します。ブロックの計算はネイティブ実装で十分な規模です。
