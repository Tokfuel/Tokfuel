## はじめに

使用量をプロジェクト別に分解します。コスト・トークン・セッション数・Skill / MCP の活動量で
プロジェクトをランキング表示し、期間フィルタを添えます。「お金とクォータは実際どこに消えて
いるのか」に答える機能です。

## 動機

プロジェクト別コストは ccusage と CCSeva の双方が備え、もっともよく挙げられる機能のひとつ
です。合計額を「実験リポジトリを片付ける」「うるさい MCP サーバーを調整する」といった行動に
変換できるからです。本アプリのトランスクリプトは `~/.claude/projects/<エンコード済みパス>/`
配下にあり、すべてのエントリが最初からプロジェクトで分類されているため、この軸は追加コスト
なしで手に入ります。さらに本アプリだけは、すでにデコードしている Skill / MCP / エージェント
の活動と結合できます。「どのプロジェクトでどのツールが予算を燃やしているか」を見せるツールは
競合に存在せず、本アプリの主要な差別化軸（トークン集計にとどまらないトランスクリプト内容の
分析）を深める提案です。

## 詳細設計

- **集計**: スキャンパイプライン（`TranscriptScanner` / `UsageStore`）を拡張し、エントリごと
  のプロジェクトキーを保持して、プロジェクト単位でコスト・トークン・セッション・ツール呼び
  出しを集計します。ディレクトリ名を読めるパスに復元し、表示用の別名も設定できるようにします。
- **UI**: `PopoverView` に「Projects」タブ（またはセクション）を追加します。コスト順のバーと
  全体に占める割合を示し、行を展開するとそのプロジェクトのモデル構成と上位の Skill / MCP
  サーバーが見えるようにします。
- **期間フィルタ**: 今日 / 7 日 / 30 日 / 全期間。未整理のアイデアにある Tools タブの期間
  フィルタと共通化（または同じ挙動に）します。
- **コストの出どころ**: python3 があるときは retok のエントリ別価格を使い、ないときはトークン
  数のみを（その旨明示して）表示し、グレースフルデグラデーションの原則を守ります。ネイティブ
  価格計算は [CU-0002](../CU-0002-native-swift-cost-analysis/CU-0002-native-swift-cost-analysis-ja.md)
  で解消されます。

## 検討した代替案

**プロジェクト別の予算・アラート。** 後続に回します。まず内訳を出荷し、必要になったら
CU-0001 の仕組みをプロジェクト単位に流用できます。

**グラフを備えた専用ダッシュボードウィンドウ。** 今回は不採用。メニューバーのポップオーバー
こそが製品であり、展開可能なランキングリストならそこに収まります。手狭になったら別項目と
して検討します。
