## はじめに

ポップオーバーのヘッダーに歯車ボタンを置き、設定ウィンドウを追加します。ログイン時起動、メニュー
バーの表示内容、レポートの既定期間と言語、予算設定、そしてどんなマシン構成でも動くようにするため
のスキャン場所（Claude ディレクトリとリポジトリルート）を扱います。

## 動機

すべてが作者のマシンに固定されていました。トランスクリプトと skill は `~/.claude`、プロジェクト
skill は `~/ghq`、メニューバーは常にコスト、レポートは常に 30 日です。これらはどれも好みの問題で
あり、しかもパスの 2 つは、構成の違う人にとってアプリが動くかどうかを左右します。`UserDefaults`
に永続化する設定画面を一つ用意すれば、コードに触れずに一台のマシンの外でも使えるようになります。

## 詳細設計

`AppSettings`（`UserDefaults` を包む `ObservableObject` シングルトン）が持つもの：

- **ログイン時起動** — `SMAppService.mainApp` と同期（登録／解除）。初回起動時は既定でオンにして、
  「インストール＝常駐」を成り立たせます。
- **メニューバー表示** — 今日のコスト／今日のプロンプト数／アイコンのみ。
- **レポートの既定値** — 期間（7/30 日）と retok の言語（自動 / en / ja）。
- **スキャン場所** — Claude ディレクトリ（既定 `~/.claude`。トランスクリプト、グローバル skill、
  プラグイン skill をここから導出）とリポジトリルート（既定 `~/ghq`。`.claude/skills` を最大 3 階
  層まで探索するので、`~/ghq/host/org/repo` 形式でも `~/src/repo` 形式でも動きます）。各行に
  Finder のフォルダ選択と既定値に戻すボタンを付けます。
- 予算設定も同じオブジェクトに載ります（[CU-0001](../CU-0001-budget-alerts/CU-0001-budget-alerts-ja.md)）。

`AppDelegate` が published な設定を監視します。パスの変更は再走査を、言語・期間の変更は retok の
再実行を、表示の変更はステータスアイテムの再描画を引き起こします。`SettingsView` はグループ化した
`Form` を独立した `NSWindow` に載せます（アクセサリアプリなので明示的に前面化します）。

## 検討した代替案

**ユーザーが手で編集する設定ファイル。** 不採用。このアプリの利用者はメニューバーをチラ見する人
です。ピッカー付きの GUI が釣り合う操作であり、`UserDefaults` がプラットフォームの標準です。

**リポジトリルートの自動検出**（ホームディレクトリ全体を走査）。不採用。ユーザーが知っている値の
ために上限のない I/O を払うことになります。妥当な既定値を持つ設定可能なルートのほうが安価で予測
できます。

## 進捗

- [x] `AppSettings`（UserDefaults 永続化）+ `SettingsView`（グループフォーム、パス選択）。

- [x] 設定変更の監視による再走査／レポート再取得／ステータス再描画。
